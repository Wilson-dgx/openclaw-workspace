## 1. 1password

### 功能
1Password CLI (op) 集成，用于：
- 安装和配置 1Password CLI
- 管理多账户登录
- 安全读取密码和密钥
- 通过 `op run` / `op inject` 注入环境变量

### 使用方法

```bash
# 安装
brew install 1password-cli

# 登录
op signin --account my.1password.com

# 验证访问
op whoami

# 列出保险库
op vault list

# 读取密码
op item get "Item Name" --fields password

# 注入环境变量
op run --env-file=".env.op" -- npm start
```

### 运行原理
- 通过 1Password 桌面应用集成进行认证
- 使用 tmux 会话保持持久登录状态
- 所有命令在专用 tmux 会话中运行，避免重复提示
- 密码永不在日志、聊天或代码中明文显示
- 支持 `op run` 和 `op inject` 进行安全注入

### 适用场景
- 需要访问敏感凭证（API密钥、数据库密码）
- 多账户环境管理
- CI/CD 环境变量注入
- 安全脚本自动化

## 2. ai-meeting-notes

### 功能
将杂乱的会议笔记转换为清晰的任务列表：
- 自动提取会议摘要
- 识别行动项（Action Items）
- 提取负责人和截止日期
- 保存为结构化 Markdown 文件
- 集成待办事项追踪系统

### 使用方法

**输入：**
```
marketing sync 1/27
sarah - need to finalize the q1 campaign, she said friday
budget discussion - mike thinks we need 50k, approved
delay on product launch - 2 weeks, waiting for legal
john will send assets by wed
need to figure out vendor situation still
next sync thursday 2pm
```

**AI 会自动：**
1. 提取会议主题和日期
2. 生成 2-3 句摘要
3. 提取所有行动项（负责人 + 任务 + 截止日期）
4. 识别决策点
5. 保存为 `meeting-notes/2025-01-27_marketing-sync.md`
6. 提示添加到待办列表

**输出格式：**
```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📋 Marketing Sync — 2025-01-27
Duration: 30 min | Attendees: Sarah, Mike, John
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

SUMMARY
Marketing sync covering Q1 campaign, budget approval ($50k), 
and product launch timeline adjustments due to legal review.

⚡ ACTION ITEMS (4 of 4)
1. [ ] @Sarah: Finalize Q1 campaign — Friday
2. [ ] @John: Send assets — Wednesday
3. [ ] @Mike: Confirm budget allocation ($50k approved)
4. [ ] @Team: Resolve vendor situation — TBD

✅ KEY DECISIONS
• Budget approved at $50k
• Product launch delayed 2 weeks (waiting for legal)

📎 Saved: meeting-notes/2025-01-27_marketing-sync.md

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Add to your to-do list?
• "all" — Add all 4 items
• "1,2,4" — Add specific items
• "none" — Skip
```

### 运行原理
1. **内容识别**：自动识别输入类型（原始笔记、转录文本、邮件、聊天记录）
2. **信息提取**：
   - 会议主题（用于文件名）
   - 日期（如果未提及，使用当天日期）
   - 摘要（2-3 句概述）
   - 行动项（负责人 + 任务 + 截止日期）
   - 决策点
   - 开放问题
   - 下一步
3. **文件保存**：格式为 `YYYY-MM-DD_topic.md`（日期在前，便于排序）
4. **待办集成**：可选添加到 `todo.md` 进行追踪

### 适用场景
- 会议后整理行动项
- 处理语音转录
- 分析邮件线程
- 提取聊天记录中的任务
- 管理项目跟进事项

## 4. apple-reminders

### 功能
通过 `remindctl` CLI 管理 Apple Reminders：
- 查看今日/明日/本周/过期提醒
- 创建带截止日期的提醒
- 管理提醒列表
- 标记完成/删除提醒
- JSON/纯文本输出

### 使用方法

```bash
# 查看提醒
remindctl                    # 今日
remindctl today              # 今日
remindctl tomorrow           # 明日
remindctl week               # 本周
remindctl overdue            # 过期
remindctl all                # 全部
remindctl 2026-01-04         # 特定日期

# 管理列表
remindctl list               # 列出所有列表
remindctl list Work          # 显示特定列表
remindctl list Projects --create    # 创建列表
remindctl list Work --delete        # 删除列表

# 创建提醒
remindctl add "Buy milk"
remindctl add --title "Call mom" --list Personal --due tomorrow
remindctl add --title "Meeting prep" --due "2026-02-15 09:00"

# 完成/删除
remindctl complete 1 2 3     # 按 ID 完成
remindctl delete 4A83 --force  # 按 ID 删除

# 输出格式
remindctl today --json       # JSON 格式
remindctl today --plain      # TSV 格式
remindctl today --quiet      # 仅显示计数
```

### 运行原理
- 通过 Apple Event 与 Reminders.app 交互
- 需要 macOS 系统
- 首次使用需授权 Reminders 权限
- 数据自动同步到 iPhone/iPad

### 适用场景
- 个人待办管理（与 iOS 同步）
- 创建带截止日期的任务
- 快速添加提醒
- 查看过期任务

## 5. automation-workflows

### 功能
设计和实施自动化工作流：
- 识别自动化机会
- 选择自动化工具（Zapier/Make/n8n）
- 设计工作流
- 测试和维护自动化
- 计算自动化 ROI

### 使用方法

**Step 1: 识别自动化机会**

跟踪一周内所有任务，计算时间成本：
```
Time Cost = (Minutes per task × Frequency per month) / 60
```

**好候选：**
- ✅ 重复性高
- ✅ 规则明确
- ✅ 频率高
- ✅ 耗时长（10+ 分钟）

**Step 2: 选择工具**

| Tool | 最适合 | 价格 | 学习曲线 | 能力等级 |
|------|--------|------|----------|----------|
| **Zapier** | 简单 2-3 步工作流 | $20-50/月 | 简单 | 低-中 |
| **Make** | 可视化多步工作流 | $9-30/月 | 中等 | 中-高 |
| **n8n** | 复杂、开发者友好、自托管 | 免费（自托管）或 $20/月 | 中-难 | 高 |

**Step 3: 设计工作流**

```
TRIGGER: 什么事件启动工作流？
  示例: "Google Sheets 添加新行"

CONDITIONS (可选): 是否每次都运行？
  示例: "仅当 Status = 'Approved'"

ACTIONS: 应该发生什么？
  Step 1: [action]
  Step 2: [action]
  Step 3: [action]

ERROR HANDLING: 失败时怎么办？
  示例: "发送 Slack 消息"
```

**示例工作流（潜在客户捕获）：**
```
TRIGGER: 网站表单提交

CONDITIONS: Email 字段不为空

ACTIONS:
  Step 1: 添加到 CRM（Airtable/HubSpot）
  Step 2: 发送欢迎邮件（ConvertKit）
  Step 3: 创建跟进任务（Notion）
  Step 4: Slack 通知："New lead: [Name]"

ERROR HANDLING: 如果 Step 1 失败，发送邮件警报
```

**Step 6: 计算 ROI**

```
Time Saved per Month (hours) = (Minutes per task / 60) × Frequency per month
Cost = (Setup time in hours × $50/hour) + Tool cost per month
Payback Period (months) = Setup cost / Monthly time saved value

如果回本期 < 3 个月 → 值得
如果回本期 > 6 个月 → 可能不值得
```

### 运行原理
1. **审计**：跟踪所有任务，计算时间成本
2. **筛选**：识别重复、规则明确、高频、耗时的任务
3. **设计**：绘制工作流图（触发器 + 条件 + 动作）
4. **实施**：在选择的工具中构建工作流
5. **测试**：用真实数据测试，处理边缘情况
6. **维护**：每周检查错误，每月审计工作流

### 适用场景
- 减少重复性工作
- 跨工具自动化
- 客户入驻流程
- 内容分发
- 发票和付款跟踪

## 7. document-pro

### 功能
文档处理技能：
- PDF 读取与提取
- Word 文档解析
- PowerPoint 提取
- Excel 数据提取
- 文档格式转换

### 使用方法

**PDF 处理：**
```python
# 提取文本
import pdfplumber

with pdfplumber.open("document.pdf") as pdf:
    for page in pdf.pages:
        text = page.extract_text()
        print(text)

# 提取表格
with pdfplumber.open("document.pdf") as pdf:
    table = pdf.pages[0].extract_tables()
```

**Word 文档：**
```python
from docx import Document

doc = Document("document.docx")
for para in doc.paragraphs:
    print(para.text)

# 提取表格
for table in doc.tables:
    for row in table.rows:
        print([cell.text for cell in row.cells])
```

**PowerPoint：**
```python
from pptx import Presentation

prs = Presentation("presentation.pptx")
for slide in prs.slides:
    for shape in slide.shapes:
        if shape.has_text_frame:
            print(shape.text)
```

### 支持的格式

| 格式 | 读取 | 写入 | 工具 |
|------|------|------|------|
| PDF | ✅ | ✅ | pdfplumber, PyPDF2 |
| DOCX | ✅ | ✅ | python-docx |
| PPTX | ✅ | ❌ | python-pptx |
| XLSX | ✅ | ✅ | openpyxl |
| TXT | ✅ | ✅ | 内置 |
| Markdown | ✅ | ✅ | 内置 |

### 运行原理
1. **识别文档类型** → 选择正确的工具
2. **读取内容** → 提取文本、表格、图片
3. **分析信息** → 理解结构、提取要点
4. **总结呈现** → 用中文总结给用户

### 适用场景
- 分析 PDF 报告
- 提取 Word 文档内容
- 读取 PPT 演示文稿
- 处理 Excel 数据
- 文档摘要生成

## 8. email-to-calendar

### 功能
从邮件中提取日历事件并创建日历条目：
- 两种模式：直接收件箱监控 / 转发邮件处理
- 智能入职配置
- 事件跟踪
- 待处理邀请提醒
- 撤销支持
- 截止日期检测
- 邮件通知

### 使用方法

**处理邮件：**
```bash
SCRIPTS_DIR="$HOME/.openclaw/workspace/skills/email-to-calendar/scripts"

# 读取邮件
"$SCRIPTS_DIR/email_read.sh" --email-id "<messageId>"

# 搜索邮件
"$SCRIPTS_DIR/email_search.sh" --query "in:inbox is:unread" --max 20 --include-body

# 创建事件
"$SCRIPTS_DIR/create_event.sh" \
    "$CALENDAR_ID" \
    "Event Title" \
    "February 11, 2026" \
    "9:00 AM" \
    "5:00 PM" \
    "Description" \
    "$ATTENDEE_EMAILS" \
    "" \
    "$EMAIL_ID"

# 检查重复
"$SCRIPTS_DIR/lookup_event.sh" --email-id "$EMAIL_ID"

# 查看待处理邀请
"$SCRIPTS_DIR/list_pending.sh" --summary

# 撤销更改
"$SCRIPTS_DIR/undo.sh" last
```

### 工作流程

1. **读取邮件内容**
2. **提取事件信息**（标题、日期、时间、URL、截止日期）
3. **展示给用户并等待确认**
4. **检查重复**（本地跟踪 + 日历搜索）
5. **创建日历事件**（自动跟踪）
6. **处理邮件状态**（标记已读/归档）

### 截止日期检测

当检测到截止日期（RSVP、注册、购票等）时，创建**两个事件**：

**1. 主事件**（带警告）：
```
*** ACTION REQUIRED: GET TICKETS BY FEB 15 ***

Event Link: https://example.com/tickets

Spring Concert at Downtown Theater
Doors open at 7 PM
```

**2. 截止日期提醒**：
```
DEADLINE: Get tickets for Spring Concert
Date: February 15, 2026
Time: 9:00 AM
Action: Get tickets
```

### 运行原理
- 使用 `gog` CLI 与 Google 服务交互
- **禁止直接调用 gog** - 必须使用包装脚本
- 本地跟踪所有创建的事件（防止重复）
- 支持 24 小时内撤销
- 忽略日历通知邮件（`calendar-notification@google.com`）

### 适用场景
- 自动提取会议邀请
- 处理活动通知
- 跟踪 RSVP 截止日期
- 批量处理邮件中的事件

## 11. gog

### 功能
Google Workspace CLI：
- Gmail（搜索、发送）
- Calendar（事件管理）
- Drive（文件搜索）
- Contacts（联系人列表）
- Sheets（读写数据）
- Docs（导出文档）

### 使用方法

**设置（一次性）：**
```bash
# 设置凭据
gog auth credentials /path/to/client_secret.json

# 添加账户
gog auth add you@gmail.com --services gmail,calendar,drive,contacts,sheets,docs

# 查看账户列表
gog auth list
```

**常用命令：**
```bash
# Gmail
gog gmail search 'newer_than:7d' --max 10
gog gmail send --to a@b.com --subject "Hi" --body "Hello"

# Calendar
gog calendar events <calendarId> --from <iso> --to <iso>

# Drive
gog drive search "query" --max 10

# Contacts
gog contacts list --max 20

# Sheets
gog sheets get <sheetId> "Tab!A1:D10" --json
gog sheets update <sheetId> "Tab!A1:B2" --values-json '[["A","B"],["1","2"]]' --input USER_ENTERED
gog sheets append <sheetId> "Tab!A:C" --values-json '[["x","y","z"]]' --insert INSERT_ROWS
gog sheets clear <sheetId> "Tab!A2:Z"
gog sheets metadata <sheetId> --json

# Docs
gog docs export <docId> --format txt --out /tmp/doc.txt
gog docs cat <docId>
```

### 运行原理
- 通过 OAuth 2.0 认证
- 调用 Google API

## 13. meeting-prep

### 功能
自动化会议准备和每日提交总结：
- 检查 Google Calendar 即将到来的会议
- 从 GitHub commits 生成 standup 更新
- 发送每日开发总结
- 提取视频会议链接

### 使用方法

**设置：**
1. **Google Calendar OAuth**：
   - 在 Google Cloud Console 创建 OAuth 凭据
   - 启用 Google Calendar API
   - 创建 OAuth 2.0 Desktop 凭据
   - 存储 `client_secret.json` 在 `credentials/`
   - 授权并存储令牌在 `credentials/calendar_tokens.json`

2. **GitHub Token**：
   - 创建经典 Personal Access Token（`repo` 权限）
   - 存储在 `credentials/github_token`

**工作流程：**

1. **会议准备检查**（每 15 分钟运行）：
   - 查询未来 45 分钟内的会议
   - 筛选带有 Google Meet 链接的会议
   - 如果会议在 30-45 分钟后且未通知：
     - 询问用户："会议 [title] 在 X 分钟后。上次更新是什么时候？检查哪些仓库？"
   - 如果会议在 10-20 分钟后：
     - 从 commits 生成更新
     - 发送格式化更新

2. **每日提交总结**（每日结束时运行）：
   - 从配置的仓库获取当天所有 commits
   - 包括所有开发者
   - 按仓库和子目录分组
   - 包含作者姓名
   - 发送总结

**API 参考：**
```bash
# 检查日历
NOW=$(date -u +%Y-%m-%dT%H:%M:%SZ)
LATER=$(date -u -d "+45 minutes" +%Y-%m-%dT%H:%M:%SZ)
TOKEN=$(jq -r '.access_token' credentials/calendar_tokens.json)

curl -s "https://www.googleapis.com/calendar/v3/calendars/primary/events?timeMin=$NOW&timeMax=$LATER&singleEvents=true" \
  -H "Authorization: Bearer $TOKEN" | \
  jq '[.items[] | select(.hangoutLink != null or .conferenceData != null)]'

# 获取 commits
TOKEN=$(cat credentials/github_token)
SINCE=$(date -u -d "-7 days" +%Y-%m-%dT%H:%M:%SZ)

curl -s -H "Authorization: Bearer $TOKEN" \
  "https://api.github.com/repos/ORG/REPO/commits?since=$SINCE&per_page=30"
```

### 输出格式

```
Update - [DATE]

[repo-name]

[subdirectory]
• Verbose description of change (Author)
• Another change (Author)

Today
• [user input]

Blockers
• None

Discussion
• None
```

### 运行原理
- 使用 Google Calendar API 查询即将到来的会议
- 使用 GitHub API 获取 commits
- 状态跟踪在 `data/meeting-prep-state.json`
- 纯文本输出（无 markdown、无 emoji）便于复制粘贴

### 适用场景
- 自动化 standup 更新
- 会议前准备
- 每日开发总结
- 团队进度跟踪

- 添加/移动/完成任务

### 使用方法

**常用映射：**
```
"tasks today" / "overdue" -> tasks --open --format telegram
"what's our week" -> week --days 7 --format telegram
"show tasks for Work" -> tasks --project Work --format telegram
"show board" -> board --project <name> --format telegram
"add <task> today" -> add "<task>" --today [--project <name>] --format telegram
"add <task> | <details>" -> add --text "<task> | <details>" --format telegram
"capture <text>" -> capture "<text>" --format telegram
"mark <title> done" -> done "<title>"
"show config" -> config show
```

**注意：**
- 如果用户包含 ` | `（空格-管道-空格），优先使用 `--text "<title | details | due 2026-01-23>"`
- 不要猜测分隔符如 "but" 或 "—"；仅在明确的 ` | ` 上分割
- 对于笔记，优先使用 `note add <selector...> -- <text...>` 以避免歧义

### 运行原理
- 路由任务相关请求到 `tasker_cmd`
- 对于自然语言，翻译请求为 CLI 参数
- 对于 `/task ...`，传递参数不变
- 优先使用人类可读输出
- 对于聊天友好的输出（Telegram/WhatsApp），添加 `--format telegram`

### 适用场景
- 日常任务管理
- 查看待办列表
- 项目任务追踪
- 快速添加任务

## 21. things-mac

### 功能
通过 `things` CLI 管理 Things 3：
- 读取本地 Things 数据库（inbox/today/upcoming/search）
- 添加/更新 todos（通过 URL scheme）
- 管理项目和区域
- 标签管理

### 使用方法

**设置：**
```bash
# 安装（Apple Silicon 推荐）
GOBIN=/opt/homebrew/bin go install github.com/ossianhempel/things3-cli/cmd/things@latest

# 如果 DB 读取失败：授予 **Full Disk Access**
# - 手动运行：Terminal
# - Gateway 运行：Clawdbot.app

# 可选：设置 THINGSDB 指向 ThingsData-* 文件夹
# 可选：设置 THINGS_AUTH_TOKEN 避免 --auth-token
```

**只读（DB）：**
```bash
things inbox --limit 50
things today
things upcoming
things search "query"
things projects
things areas
things tags
```

**写入（URL scheme）：**
```bash
# 安全预览
things --dry-run add "Title"

# 添加
things add "Buy milk"
things add "Buy milk" --notes "2% + bananas"
things add "Book flights" --list "Travel"
things add "Pack charger" --list "Travel" --heading "Before"
things add "Call dentist" --tags "health,phone"
things add "Trip prep" --checklist-item "Passport" --checklist-item "Tickets"

# 从 STDIN（多行 => title + notes）
cat <<'EOF' | things add -
Title line
Notes line 1
Notes line 2
EOF

# 修改（需要 auth token）
things search "milk" --limit 5  # 获取 ID
things update --id <UUID> --auth-token <TOKEN> "New title"
things update --id <UUID> --auth-token <TOKEN> --notes "New notes"
things update --id <UUID> --auth-token <TOKEN> --append-notes "..."
things update --id <UUID> --auth-token <TOKEN> --prepend-notes "..."
things update --id <UUID> --auth-token <TOKEN> --list "Travel" --heading "Before"
things update --id <UUID> --auth-token <TOKEN> --tags "a,b"
things update --id <UUID> --auth-token <TOKEN> --add-tags "a,b"
things update --id <UUID> --auth-token <TOKEN> --completed
things update --id <UUID> --auth-token <TOKEN> --canceled

# 安全预览
things --dry-run update --id <UUID> --auth-token <TOKEN> --completed
```

**删除 todo？**
- 当前 `things3-cli` 不支持删除/移至垃圾箱
- 选项：使用 Things UI 删除，或标记为 `--completed` / `--canceled`

### 运行原理
- **只读**：直接读取 Things SQLite 数据库
- **写入**：通过 Things URL scheme（`things:///...`）
- 需要 macOS
- `--dry-run` 打印 URL 而不打开 Things
- 更新操作需要 auth token

### 适用场景
- 查看 Things 任务
- 快速添加 todos
- 项目管理
- 标签组织
- 自动化任务创建
